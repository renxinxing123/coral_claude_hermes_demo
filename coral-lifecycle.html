CoralOS
Infrastructure

Protocol Lifecycle

From configuration to multi-agent collaboration

01
Configure Coral Server
Edit config.toml to register agent directories. Coral Server scans each path for coral-agent.toml.
# config.toml
local_agents = [
  "./hermes",
  "./claude_code"
]
02
Configure Each Agent
Each agent directory contains two files that define identity and bootstrap behavior.
hermes/
  coral-agent.toml -- name, description, runtime
  startup.sh -- receives MCP URL, patches config

claude_code/
  coral-agent.toml -- name, description, runtime
  startup.sh -- writes .mcp.json with MCP URL
coral-agent.toml defines [runtimes.executable]
03
Start Coral Server
./gradlew run

Server starts on http://localhost:5555. Reads all coral-agent.toml files and registers agents. Console available at /ui/console.
04
Create a Session
POST to /api/v1/local/session specifying which agents to include.
agents: [
  { name: "hermes-agent" },
  { name: "claude-code-agent" }
]
groups: [["hermes-agent", "claude-code-agent"]]
Coral Server generates a unique MCP URL per agent
05
Coral Executes startup.sh
For each agent, Coral runs bash startup.sh with environment variables.
$CORAL_CONNECTION_URL -- unique MCP endpoint
$CORAL_AGENT_ID -- agent name
$CORAL_SESSION_ID -- session UUID
Hermes — patches global ~/.hermes/config.yaml with MCP URL
Claude Code — writes .mcp.json with MCP URL
06
User Starts Agents Manually
In separate terminals:
Terminal 1 (Hermes):
  $ hermes chat

Terminal 2 (Claude Code):
  $ cd claude_code && claude
Both agents connect to Coral via MCP and can communicate through threads and messages.

Environment Variables

$CORAL_AGENT_ID = hermes-agent | claude-code-agent
